# RadixScope v2 숫자 처리 명세

[한국어 README](../../README.ko.md) | [English](../specification.md)

## 기본 규칙

- 지원 진법은 2~36입니다.
- 입력 숫자의 영문 대소문자는 구분하지 않습니다. 출력은 대문자를 사용합니다.
- 코어 연산은 정확한 값을 사용하며 이진 부동소수점에 의존하지 않습니다.
- 입력 앞뒤 공백은 무시하지만 숫자 내부 공백은 허용하지 않습니다.
- 모든 숫자는 선택한 진법에서 유효해야 합니다.
- 정확한 수 모델의 0은 항상 양의 부호로 정규화합니다.

## 숫자 문자

숫자 값에는 다음 문자를 사용합니다.

```text
0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ
```

`A`는 10, `Z`는 35를 나타냅니다.

## 입력 형식

`parse_number`는 진법을 별도 인자로 받습니다. `parse_literal`은 숫자 문자열에서
진법을 읽습니다.

```text
sign      = "+" | "-"
integer   = sign? digit+
finite    = sign? digit+ "." digit+
ratio     = integer "/" integer
recurring = sign? digit+ "." digit* "(" digit+ ")"
number    = ratio | recurring | finite | integer
```

| 입력 | 진법 | 정확한 값 |
| --- | ---: | ---: |
| `-101` | 2 | `-5` |
| `A.F` | 16 | `175/16` |
| `1/3` | 10 | `1/3` |
| `A/10` | 16 | `5/8` |
| `0.(3)` | 10 | `1/3` |
| `0.1(6)` | 10 | `1/6` |
| `0.(01)` | 2 | `1/3` |

분수의 분자와 분모는 모두 선택한 진법을 사용합니다. 분모 0은 허용하지 않습니다.

## 정확한 수 모델

허용된 모든 숫자는 유리수로 정규화합니다.

- 분자와 분모를 최대공약수로 약분합니다.
- 분모는 항상 양수입니다.
- 정수의 분모는 `1`입니다.
- 값이 같은 입력은 동일한 정확한 값을 만듭니다.

## 변환 동작

- 정수 변환은 정확한 값 전체를 사용합니다.
- 소수부 변환은 나머지를 추적해서 순환 구간을 탐지합니다.
- 유한소수 결과에는 순환 구간이 없습니다.
- 순환소수 결과는 `0.(3)`처럼 괄호로 표시합니다.
- 자릿수 제한과 반올림은 출력 표현만 바꾸며 저장된 정확한 값은 바꾸지 않습니다.
- 완전한 순환소수 표현을 다시 값으로 변환하면 원래 유리수와 같아야 합니다.

## 혼합 진법 리터럴

접두사 없는 리터럴은 10진수입니다. `0b`, `0o`, `0x`는 각각 2, 8, 16진수이며
접두사와 숫자는 대소문자를 구분하지 않습니다. `base#digits`는 2~36진법을 선택하고,
`base` 부분은 항상 10진수로 씁니다. 유한소수와 순환소수는 `parse_number`와 같은
문법을 사용하므로 `0xA.F`, `2#0.(01)`, `0.1(6)`은 정확한 값입니다.
정수부가 필수이므로 `.5`, `0x.F`는 허용하지 않습니다. 지수 표기법은 지원하지 않습니다.

`parse_literal`은 단일 리터럴의 앞 부호와 바깥 공백을 허용합니다.
수식에서 부호는 단항 연산자입니다. 슬래시는 각자 진법을 갖는 두 리터럴 사이의
나눗셈이므로 `0xA / 10`은 `1`, `0xA / 16#10`은 `5/8`입니다.
같은 진법의 독립적인 분수 입력에는 `parse_number("A/10", 16)`을 사용합니다.

```python
from radixscope.core import ExactValue, evaluate_expression, parse_literal

assert parse_literal("0xA.F") == ExactValue(175, 16)
assert evaluate_expression("0xFF + 0b10") == ExactValue(257)
assert evaluate_expression("16#FF + 2#10") == ExactValue(257)
assert evaluate_expression("(0x10 + 2) ** -2") == ExactValue(1, 324)
```

## 수식 토큰화

`tokenize_expression`은 숫자 리터럴, 연산자, 묶음 괄호를 분리합니다.
각 불변 토큰에는 종류, 원문, 0부터 시작하는 시작 위치와 끝 위치가 포함됩니다.
범위는 시작 위치를 포함하고 끝 위치는 제외합니다. 종료 토큰은 입력 끝을 표시합니다.
토큰 사이 공백은 무시하지만 리터럴 내부 공백은 허용하지 않습니다.
숫자와 진법 표시는 ASCII를 사용합니다. 부호는 별도 토큰이고 순환 괄호는 숫자
리터럴에 속합니다. `**`는 곱셈 토큰 두 개가 아닌 거듭제곱 토큰 하나로 만듭니다.

## 수식 파싱과 계산

`parse_expression`은 리터럴·단항·이항 노드로 이루어진 불변 트리를 반환합니다.
`evaluate_parsed_expression`은 트리를 계산하며 `evaluate_expression`은 두 과정을
합칩니다. 모든 리터럴과 중간 결과는 정확한 유리수로 유지합니다.

```text
expression = product (("+" | "-") product)*
product    = unary (("*" | "/") unary)*
unary      = ("+" | "-") unary | power
power      = primary ("**" unary)?
primary    = literal | "(" expression ")"
```

덧셈·뺄셈·곱셈·나눗셈은 왼쪽부터 결합합니다. 거듭제곱은 오른쪽부터 결합하므로
`10#2**10#3**10#2`는 `512`입니다. 거듭제곱이 앞 부호보다 우선하므로
`-10#2**10#2`는 `-4`입니다. 지수는 계산 결과가 정수여야 하며 음의 지수는
정확한 역수를 만듭니다. 0의 음의 거듭제곱과 0으로 나누기는 허용하지 않습니다.
0의 0제곱은 `1`입니다. 오류는 연산자나 토큰 위치를 알려주며 과도한 중첩은
도메인 오류를 발생시킵니다. 변수, 대입, 함수 호출, 곱셈 기호 생략은 지원하지 않습니다.

데스크톱의 정확한 변환은 소수부를 최대 1000자리까지 표시하고 부분 전개에는
말줄임표와 해당 진법을 표시합니다. 과정 화면에서는 단계 제한을 조절할 수 있습니다.
`trace_value(..., max_steps=...)`는 원래 유리수를 보존하고, 전개 종료나 순환 확인 전에
제한에 도달하면 `complete=False`로 표시합니다. 코어의 기본 동작에는 제한이 없습니다.
부분 과정은 유한소수라고 판정하지 않습니다.

## 고정 비트 정수 모델

`FixedWidthInteger(value, width, signed=False)`는 양의 비트 폭을 명시한 불변 정수입니다.
부호 없는 범위는 `0`~`2**width - 1`, 부호 있는 범위는
`-2**(width - 1)`~`2**(width - 1) - 1`이며 생성 시 범위를 검사합니다.
비트 폭은 8의 배수가 아니어도 됩니다. 불리언과 정수가 아닌 값은 거부합니다.

`from_exact`, `from_text`는 유리수 코어와 숫자 파서를 연결합니다.
소수 값은 잘라내지 않고 거부합니다. `exact` 속성은 수학적 값을 `ExactValue`로
반환합니다. `resize`는 값과 부호 설정을 유지하고 새 범위를 검사하며,
비트를 버리거나 값을 감싸지 않습니다.

## 부호 있는 해석과 부호 없는 해석

`bit_pattern`, `bits`는 앞의 음수 부호 없이 고정 비트 값을 표현합니다.
`reinterpret(signed=...)`은 폭과 모든 비트를 유지하고 해석만 바꿉니다.
`interpret_bit_pattern`은 같은 패턴의 부호 없는 값, 2의 보수 값, 부호 비트,
폭을 맞춘 이진 문자열, 대문자 16진 문자열을 반환합니다.

`from_bits`에 폭을 주지 않으면 원시 이진 문자열의 길이를 사용합니다.
더 큰 폭을 명시하면 0으로 확장한 뒤 부호를 해석하며, 폭을 넘는 문자열 비트는
거부합니다. 따라서 `11111111`은 8비트 부호 있는 값으로 `-1`, 16비트 부호 있는
값으로 `255`입니다. `parse_bit_pattern`은 지정한 진법의 정수 숫자를 읽은 뒤 패턴을
해석합니다. `from_text`는 수학적 값을 읽으므로 부호 있는 `-1`과 패턴 `FF`는 서로
다른 입력 경로입니다. 어느 경로도 범위 밖의 입력을 자동으로 감싸지 않습니다.

## 범위와 오버플로 분석

`analyze_range`는 수학적 정수를 유지하고 목적 범위를 알려줍니다.
`overflowed`는 범위 초과 여부이며 `checked`는 초과 시 `IntegerRangeError`를 발생시킵니다.
`wrapped`는 명시적으로 결과를 `2**width`로 나눈 나머지로 줄인 뒤 부호를 해석합니다.
감싼 결과가 정확한 결과를 덮어쓰지는 않습니다.

`analyze_arithmetic`은 비트 폭과 부호 설정이 같은 두 피연산자의 덧셈·뺄셈·곱셈을
분석합니다. 부호 있는 오버플로와 부호 없는 오버플로는 각각의 수학적 범위로 판단합니다.
예를 들어 부호 있는 8비트 `127 + 1`은 정확히 `128`이며, 오버플로가 발생하고 감싼
결과는 `-128`입니다. 부호 없는 `255 + 1`은 `0`으로 감쌉니다.
형식이 다른 피연산자는 먼저 명시적으로 폭이나 해석을 바꿔야 합니다.

## 고정 비트 연산

고정 비트 값은 `&`, `|`, `^`, `~`, `<<`, `>>`를 지원합니다.
이항 비트 연산의 피연산자는 폭과 부호 설정이 같아야 합니다. 결과는 그 형식을
유지하며 NOT과 왼쪽 시프트는 선택한 폭으로 마스킹합니다. 원래 피연산자는 바뀌지 않습니다.

부호 있는 값의 `>>`는 부호 비트를 반복하는 산술 시프트입니다.
부호 없는 값은 0으로 채웁니다. `logical_right_shift`는 항상 0으로 채우고 선언된
형식을 유지합니다. 시프트 횟수는 불리언을 제외한 음이 아닌 정수여야 합니다.
횟수가 폭 이상이면 이동한 비트는 모두 사라집니다. 왼쪽 시프트와 논리 오른쪽 시프트는
0이 되며, 음의 부호 있는 값의 산술 오른쪽 시프트는 `-1`이 됩니다.
이 연산은 `FixedWidthInteger`에 적용합니다. 유리수 수식 문법은 문서에 적힌
산술 연산자만 지원합니다.

## 엔디언 바이트와 ASCII 표현

`encode_bytes`는 고정 비트 패턴을 빅 엔디언 또는 리틀 엔디언으로 직렬화합니다.
앞의 0 바이트를 포함해 정확히 `ceil(width / 8)`바이트를 사용합니다.
바이트 순서는 바이트의 배열만 바꾸고 각 바이트 내부 비트는 바꾸지 않습니다.
부호 있는 음수는 2의 보수 패턴을 유지합니다.

최상위 부분 바이트의 사용하지 않는 상위 비트는 0으로 채웁니다.
예를 들어 부호 있는 5비트 `-1`은 `FF`가 아니라 `1F`입니다.
`decode_bytes`의 기본 폭은 `len(data) * 8`입니다. 바이트 경계에 맞지 않는 값을
왕복 변환하려면 원래 폭을 전달해야 합니다. 명시한 폭은 바이트 개수와 맞아야 하며,
사용하지 않는 상위 비트가 0이 아니면 버리지 않고 거부합니다.
빈 데이터는 고정 비트 정수를 표현할 수 없습니다.

`represent_bytes`는 순서가 적용된 바이트, 공백으로 구분한 대문자 16진 문자열,
ASCII 미리보기를 반환합니다. 미리보기는 `20`~`7E`의 출력 가능한 바이트를 표시하고
그 밖의 바이트는 점으로 표시하며 원래 데이터는 바꾸지 않습니다.
`encode_ascii`, `decode_ascii`는 제어 문자를 포함한 엄격하고 손실 없는 7비트 ASCII
변환입니다. ASCII 밖의 문자와 바이트는 대체하지 않고 거부합니다.

## IEEE 754 디코딩

`decode_ieee754(pattern, width=64)`는 부호 없는 원시 binary32 또는 binary64 패턴을
비트 변경 없이 해석합니다. `IEEEFormat`은 23/52비트 가수부, 8/11비트 지수부,
127/1023 지수 바이어스를 정의합니다. 다른 형식은 거부합니다.
`decode_ieee754_bytes`는 바이트 순서를 명시하며 정확히 4바이트 또는 8바이트를 받습니다.

불변 `IEEE754Value`는 부호·지수·가수부 필드, 폭을 맞춘 이진·16진 문자열,
0·비정규수·정규수·무한대·NaN 분류를 제공합니다. 유한한 `exact` 값은 가장 작은
비정규수까지 유리수로 표현합니다. `significand`에는 정규수일 때만 숨겨진 선행 1이
포함됩니다. `exponent`는 바이어스를 제거한 지수이며 0과 비정규수에는 형식의 최소
정규 지수를 사용합니다. 무한대와 NaN에는 유리수 값, 유효숫자, 바이어스를 제거한
지수가 없습니다.

부호 있는 0은 유리수 값이 0이어도 원시 패턴의 부호를 유지합니다.
NaN은 부호, quiet 비트, 페이로드를 유지하며 `nan_payload`는 quiet 비트를 제외합니다.
`to_bytes`는 모든 원시 비트를 유지하고 두 엔디언 순서를 지원합니다.
`to_float`는 Python 부동소수점으로 바꾸는 편의 기능입니다. 시그널링 NaN과
페이로드를 보존하려면 원시 패턴을 사용하세요.

형식 정의는 [Oracle 수치 계산 안내](https://docs.oracle.com/cd/E19422-01/819-3693/ncg_math.html)를
따릅니다.

## IEEE 754 인코딩

`encode_ieee754(value, width=64)`는 `ExactValue`, 정수, Python `float`를 받아
`IEEE754Value`를 반환합니다. 유리수와 정수는 먼저 Python `float`로 바꾸지 않고
목적 형식으로 직접 반올림합니다. Python `float` 입력에는 그 값의 실제 이진 표현을
사용합니다. 정확한 십진 입력에는 `ExactValue`와 숫자 파서를 사용하세요.

반올림은 가장 가까운 값으로 하며 동률이면 짝수를 선택합니다.
유효숫자 자리 올림, 점진적 언더플로, 비정규수에서 정규수로의 전환,
부호 있는 무한대로의 오버플로를 처리합니다. 최소 비정규수의 절반보다 작은 값은
부호 있는 0으로 반올림합니다. 정확히 절반이면 짝수 선택인 0을 택합니다.
오버플로 경계의 정확한 중간값은 무한대로 반올림합니다.

Python `-0.0`은 부호를 유지합니다. 유리수 0에는 부호가 없으므로
`negative_zero=True`로 음의 0을 명시적으로 만들며, 0이 아닌 값에서는 이 옵션을
거부합니다. Python 무한대는 부호를 유지하고 Python NaN은 부호를 유지한 표준 quiet
NaN이 됩니다.

`encode_ieee754_special`은 0 또는 1인 `sign_bit`로 0, 무한대, NaN을 명시적으로 만듭니다.
NaN의 `payload`에는 선행 quiet 비트가 포함되지 않습니다. `quiet=False`는 페이로드가
0이 아닐 때만 signaling NaN을 만듭니다. 페이로드는 선택한 형식에 맞아야 하며
넘치는 값을 잘라내지 않고 거부합니다. NaN이 아닌 특수값에는 페이로드를 넣을 수 없습니다.
기존 NaN 패턴을 손실 없이 다루려면 원시 디코딩과 바이트 직렬화를 사용하세요.

## 오류

코어는 다음 입력을 거부합니다.

- 2~36 범위 밖의 진법
- 빈 입력 또는 숫자 없이 부호만 있는 입력
- 선택한 진법에 없는 숫자
- 소수점, 분수 구분자, 순환 구간이 여러 개인 입력
- 비어 있는 순환 구간
- 0인 분모
- 잘못된 리터럴 접두사, 유효하지 않은 진법 표시, 지원하지 않는 숫자 문법
